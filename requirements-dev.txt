# Every optional extra, so a dev checkout runs the whole suite instead of skipping the
# parts that need a dependency the core deliberately does not ship. Everything optional is
# guarded with pytest.importorskip, so `pytest` stays green without this file — it just
# runs fewer tests and says which ones and why (`pytest -rs`).
#
# All of them begin with `-r requirements.txt`, so pip reads that file once per extra and
# sees each core pin that many times. That is fine and not a mistake to tidy up: pip only
# errors on *conflicting* requirements for one package, and these are byte-identical lines
# from one file. The alternative — extras that do not pull the core — would mean
# `pip install -r requirements-modbus.txt` alone produced a checkout that cannot start.
-r requirements-api.txt
-r requirements-modbus.txt
-r requirements-homeassistant.txt
-r requirements-lora.txt

pytest
